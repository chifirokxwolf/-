# Лимиты и завершение аренды: схема реализации

Статус: **автоматическое управление Claude ещё не подключено в версии 0.3.0**.
Работающие сейчас части — Cardinal, учёт аренды, Remail и запрет повторной выдачи.
Для браузерной части требуются проверка настоящего интерфейса Claude и тест
отзыва доступа. Документацию Claude из текущей среды получить не удалось:
сетевой прокси вернул CONNECT 403. Непроверенные адреса приватного API и селекторы
кнопок в код не добавляются.

Дополнение: реализован отдельный браузерный помощник `claude_browser_actions.py`
для нажатия **«Выйти везде»** и подтверждения. Он включён в готовую сборку,
но не запускается, пока реальный Claude-адаптер не предоставит авторизованную
страницу и проверки аккаунта/отзыва доступа. Выбор кнопок проверен в Chromium
на тестовом интерфейсе на 10 языках, а не на живых аккаунтах Claude.

## Сессия владельца

Использовать Playwright/Chromium с отдельным профилем для каждого аккаунта.
Профиль хранится на сервере рядом с данными плагина, не в Git. Cookies не
передаются покупателю и не показываются в Telegram. Страница должна подтверждать
нужный адрес аккаунта перед любой проверкой или выходом из сессий.

Первый вход владельца выполняется по почте и отдельному коду через Remail.
Если сервис потребует интерактивную проверку, аккаунт остаётся на удержании до
ручного завершения входа. Профиль сохраняется; держать вкладки всех аккаунтов
открытыми постоянно не обязательно. Количество одновременно запущенных
контекстов ограничивается ресурсами сервера.

Попытки входа владельца и покупателя идут последовательно на одном аккаунте.
Одноразовый код, которым вошёл скрипт, не выдаётся покупателю. Для покупателя
создаётся отдельная попытка. На реальном потоке необходимо проверить, что код
или ссылка работают в его браузере, а не только в браузере, запросившем письмо.
Если это не так, нужно изменить сценарий: покупатель инициирует вход, а бот
ожидает именно это письмо и выдаёт единственный код по активному заказу.

## Чтение лимитов

В сессии владельца читать раздел использования Claude: фактические проценты
пятчасового и недельного лимитов, а также указанные сервисом моменты сброса.
Если недельных ограничений несколько (например, общие и относящиеся к модели),
сохранять каждое отдельно и учитывать все, относящиеся к продаваемому доступу.
Не вычислять проценты из числа сообщений, суммы заказа или локальных логов Code.

Браузер может читать DOM или JSON-ответ, который сама страница получает во время
обычной загрузки. Второй вариант потребует проверки схемы и обновления при её
изменениях; такой запрос нельзя объявлять стабильным публичным API Claude.
Проверять числовой диапазон, нужную организацию, аккаунт и время получения данных.

Плановый опрос — раз в 60 секунд с ограничением параллелизма и задержкой после
ошибок сервиса. Перед выдачей требовать свежую успешную проверку. Если любой
учитываемый показатель больше 70%, аккаунт не участвует в новых выдачах.
Возвращать его в пул после реальной проверки значений не выше 70% и подтверждения
отсутствия прошлой аренды. Наступление предполагаемого времени сброса само по
себе не освобождает аккаунт.

Истёкшая сессия владельца, неизвестная структура ответа, ошибка сети или
непонятный процент означают «данных нет / удержание», а не 0%.
Рост использования во время оплаченной аренды запрещает следующую выдачу,
но не завершает текущую аренду раньше её срока.

## Истечение аренды и отзыв доступа

1. Хранить срок в SQLite в UTC. Отдельный планировщик проверяет просроченные
   аренды каждые 5–10 секунд и после перезапуска. При наступлении срока атомарно
   переводить аренду в состояние завершения; аккаунт остаётся занят.
2. Через сессию владельца нажать именно **«Выйти везде»** в настройках Claude
   и подтвердить действие, если появится диалог. Закрытие вкладки или локальный
   logout профиля владельца не равны отзыву доступа покупателя.
3. Проверить отзыв на отдельной контрольной сессии того же тестового аккаунта:
   после операции она больше не должна проходить аутентифицированную проверку.
   Текст об успешном нажатии кнопки сам по себе недостаточен.
4. Проверить, что ранее выданная ссылка уже не позволяет восстановить вход.
   Если срок её действия неизвестен, аккаунт нельзя автоматически освобождать.
5. Если глобальный выход завершил также сессию владельца, заново войти через
   отдельное письмо Remail, снова проверить лимиты и только затем вернуть
   аккаунт в пул.

При ошибке сохранять состояние завершения, повторять попытку с ограниченной
задержкой и показывать проблему оператору. Действие отзыва должно допускать
повторный запуск после аварии. Кнопка ручного возврата в пул не должна обходить
неподтверждённый отзыв.

Планировщик отзыва нужно отделить от очереди выдачи писем. Нынешняя версия
сериализует внешние действия одним замком; следующий этап должен использовать
отдельные очереди и блокировки на каждый аккаунт, чтобы ожидание письма для
одного аккаунта не задерживало завершение чужих аренд. Сетевой сервис всё равно
не позволяет обещать отзыв с точностью до секунды.

## Языки интерфейса

Браузерный помощник ищет именно кнопку глобального выхода по доступному имени
элемента, а не по координатам экрана. Имеются варианты для русского, английского,
украинского, немецкого, французского, испанского, португальского, китайского,
японского и корейского. Это словарь вариантов, а не утверждение, что все эти
языки сейчас доступны в интерфейсе Claude или что их формулировки уже проверены
на реальном сайте. Язык аккаунта автоматически не меняется.

Обычная кнопка «Выйти» на странице не используется: такое название допустимо
только внутри окна подтверждения после нажатия глобального выхода. Если кнопка
не найдена, найдены несколько подходящих кнопок или подтверждение неизвестно,
помощник возвращает ошибку. Аккаунт должен остаться в удержании.

В готовой сборке адаптер может импортировать функцию так:

```python
from _claude_rental_browser_actions import logout_everywhere
```

При вызове требуются две функции: `verify_account(page)` подтверждает нужный
аккаунт, `verify_revoked(timeout_ms)` проверяет отзыв прежних сессий, ссылок
и Code-токенов. Без успешной проверки помощник не возвращает `True`.
Страница настроек должна быть уже открыта. Playwright и профиль принадлежат
одному браузерному рабочему потоку; передавать его синхронную страницу между
потоками Cardinal нельзя.

## Claude Code проверяется отдельно

Ваш лот включает Claude Code, поэтому одного браузерного теста недостаточно.
Нужно авторизовать контрольный клиент Code, выполнить глобальный отзыв и проверить
как уже выданный access token, так и возможность обновления через refresh token.
Использовать доступный у Claude механизм отзыва соответствующих авторизаций,
если он есть. Локальная команда выхода на сервере не отзывает токен на компьютере
покупателя. Удаление браузерных cookies также не является такой проверкой.

Если доступного и проверенного глобального отзыва Code нет, гарантированный
авто-кик для лота «Claude PRO + Claude Code» заявлять нельзя. Тогда необходимо
либо ограничить аренду тем видом доступа, который реально отзывается, либо
изменить способ предоставления доступа с согласованием владельца.

## Что считать готовым

На тестовом аккаунте должны пройти: изоляция двух профилей, чтение обоих типов
лимитов, запрет выдачи при 70%+, правильная граница ровно 70%, истечение срока,
потеря сети при выходе, перезапуск во время отзыва, повторное выполнение отзыва,
блокировка старой ссылки и отдельная проверка Claude Code. Готовность подтверждается
реальным прекращением доступа контрольного клиента, а не только локальными тестами.
