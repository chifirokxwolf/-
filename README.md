# Claude Rental 0.2.0 — плагин FunPay Cardinal

**Установка одним файлом:** скачайте
[`dist/claude_rental_plugin.py`](dist/claude_rental_plugin.py), отправьте его
своему Telegram-боту Cardinal через `/upload_plugin`, выполните `/restart`
и откройте `/claude_rental`. Дополнительные Python-файлы для готовой сборки не нужны.
Полная инструкция: [INSTALL_PLUGIN_RU.md](INSTALL_PLUGIN_RU.md).

В меню доступны аккаунты, проверка Remail, текущие аренды, ручное исключение
аккаунтов из новых выдач, отправители писем, название лота и срок аренды.
Конфигурация и база создаются автоматически в `storage/claude_rental/`.

Реализованы SQLite-база и плагин для интерфейса `BIND_TO_NEW_ORDER`.
Реализован клиент почтового API Remail по предоставленной документации.
**Это пока не готовая система продаж:** вход в Claude, чтение лимитов и отзыв
сессий ещё требуют реального адаптера. Почтовый клиент проверен на тестовых
ответах; сквозной запрос к Remail из этой среды заблокирован сетевой политикой.
Новые выдачи по умолчанию на паузе; включение без Claude-адаптера запрещено.

Интерфейс проверен по исходникам публичного форка
[sidor0912/FunPayCardinal](https://github.com/sidor0912/FunPayCardinal),
ревизия `c09dd13be25072bb3d5cdbba33d1e0d70e477710`.
Загрузка, регистрация меню и события дополнительно проверены на предоставленном
архиве **FunPayCardinal-0.1.17.15.zip**, с его настоящим загрузчиком, классами
Telegram и событий заказа. Удалённые вызовы в этих тестах заменены имитацией.
Инициализация панели зарегистрирована через `BIND_TO_PRE_INIT`, до установки
Telegram-команд. Фоновые задачи запускаются через `BIND_TO_POST_START`.

## Подключение почты Remail

На сервере, где будет работать Cardinal, добавьте почту и персональную ссылку
Remail. Скрипт сам извлечёт из ссылки `email` и `token`; почта должна точно
совпадать с адресом в ссылке. Токен вводится скрыто и не попадает в историю команд.

```sh
python rental.py add
python rental.py status
python remail.py --account-id 1
```

Последняя команда делает реальный запрос к API и выводит количество писем,
не показывая их текст, коды или токены. ID аккаунта берётся из `status`.
Если база находится в другом месте, у обеих программ используйте одинаковый
`--db /path/to/rentals.sqlite3`.

По предоставленной документации `https://remail.aishop6.com/docs` реализованы:

| Метод | Параметры | Использование |
| --- | --- | --- |
| `GET /v1/pickup` | `email`, `token` в query | `items` с ID, отправителем, получателем и датой; состояние `fetch` |
| `GET /v1/pickup/messages/{messageId}` | тот же `email`, `token` | чтение `verificationCode` либо ссылки из `body` |

Дополнительный API key для этих двух методов в предоставленном контракте не
указан. Токен — `serviceToken` из персональной ссылки, не ключ от FunPay.
Почтовые адреса и суффиксы не заменяются; редиректы с токеном запрещены.

В `config.json` заполните `mailbox.allowed_senders` точными адресами отправителей
настоящих писем входа Claude. Узнать их можно в почте или командой:

```sh
python remail.py --account-id 1 --show-senders
```

Она показывает только отправителей. Выберите адрес реального письма Claude;
не добавляйте всех отправителей подряд. Пример Microsoft в документации не
является отправителем Claude. Пустой список запрещает выдачу кодов.

Клиент запоминает существующие ID, запрашивает вход через Claude-адаптер,
затем ждёт письмо, полученное не раньше начала запроса. Проверяются точный
получатель, разрешённый отправитель и дата. Учитываются `nextFetchAllowedAt`,
`Retry-After`, таймаут 120 секунд и ограничение размера ответа. Серверные ошибки
повторяются с задержкой; ошибки авторизации немедленно останавливают операцию.
При нескольких новых подходящих письмах выдача останавливается для ручной проверки.
ID полученного письма атомарно привязывается к заказу в SQLite перед отправкой.
Повторное использование того же письма запрещено и после перезапуска.

Поддерживаются цифровые коды длиной 4–12 символов (с сохранением начальных нулей)
и одна однозначная HTTPS-ссылка на `claude.ai` с параметрами. HTML-ссылки
извлекаются без открытия. Другие форматы требуют изменения после проверки.
Нельзя расходовать одноразовый код сначала на вход скрипта, затем отправлять его
покупателю; это разные попытки входа. Формат числовых кодов и возможность
переноса ссылки между браузерами тоже требуют проверки на реальном потоке Claude.
Отдельные входы оператора во время ожидания письма могут нарушить сопоставление:
Remail не сообщает идентификатор попытки входа Claude. Нужна исключительная
обработка попыток входа каждого аккаунта и синхронизированные часы сервера.

Секреты вводятся только локально на сервере, где работает Cardinal. Покупателю
отправляется код/ссылка Claude, а не токен Remail или ссылка на почтовый ящик.

## Проверка разработки

Python 3.12, внешние зависимости для ядра и тестов не нужны:

```sh
cd /workspace/-
python -m unittest -v
python rental.py status
python rental.py add
```

Команда `add` запрашивает почту и скрытый ввод ссылки remail. База содержит
секретные ссылки, хранится в `data/`, исключена из Git; файл имеет права 0600.
Она не зашифрована: резервные копии и доступ к серверу должны быть защищены.
Не передавайте реальные ссылки в аргументах команд или в переписке.

## Уже работающая логика

- Один незавершённый заказ на аккаунт, транзакционное резервирование SQLite.
- Заказ привязан к покупателю и чату. Повторные события не выдают новый код.
- Глобально уникальный хеш кода/ссылки не позволяет выдать то же значение в другом
  заказе. Совпадение коротких цифровых кодов также остановит выдачу; это
  консервативное ограничение требует внимания оператора.
- При значении любого лимита **больше 70%**, неизвестном значении или проверке
  старше 120 секунд аккаунт недоступен для новой аренды.
- Активная аренда продолжается при росте лимитов: меняется доступность следующих выдач.
- После истечения аренды обязательны подтверждённый выход всех сессий и новая
  проверка лимитов. При сетевой ошибке аккаунт остаётся занят.
- Новый аккаунт тоже требует первоначального подтверждённого выхода всех сессий.
- Таймер на 5 часов начинается после подтверждения отправки. При ошибке отправки
  сохраняется блокировка; до истечения таймера попытки выдачи не повторяются.
- Правило для предоставленного названия лота выдаёт ровно 5 часов. Бонус за отзыв
  пока не реализован и не добавляется автоматически. Количество товара по умолчанию
  не умножает срок; это можно отдельно включить в правиле.

Гарантировать строго однократную доставку через сеть нельзя без поддержки
идемпотентности со стороны FunPay: сервер мог принять сообщение до обрыва связи.
Здесь выбран режим без автоматической повторной выдачи при неопределённом результате.
Такие заказы, а также нехватка свободных аккаунтов требуют внимания оператора.
Заказы передаются в фоновую очередь, чтобы ожидание почты не блокировало
обработчик Cardinal. Очередь не восстанавливается после остановки; возвраты,
бонус за отзыв и автоматическая повторная обработка не реализованы.

## Что необходимо для подключения

Почтовая часть уже подключена к плагину. Нужен модуль Claude-адаптера с
`create(config)`, возвращающий объект с методами:

```python
usage(account) -> tuple[float, float]  # проценты за 5 часов и 7 дней
request_login(account, order_id)      # запросить письмо входа для покупателя
revoke_all(rental) -> bool            # True только после проверки отзыва доступа
```

`account` содержит `id`, `email`, `pickup`; `rental` содержит также `account_id`
и `order_id`. Методы получения ссылки и отзыва должны быть идемпотентны по заказу.
Адаптер не должен журналировать ссылки, cookies или тексты писем.
Необходимо проверить одноразовость и срок жизни ссылки: выход
из сессий недостаточен, если прежняя ссылка всё ещё позволяет войти повторно.
Проценты берутся из реальных данных Claude, а не рассчитываются по времени.

Для разработки провайдера требуются доступ к `remail.aishop6.com`, `claude.ai`
и для сквозной проверки — `funpay.com`. В текущей среде запрос к remail отклонён
сетевым прокси (CONNECT 403); сохранение настроек среды вернуло ошибку.
Почтовый контракт получен от пользователя и покрыт тестами. Доступные операции
Claude и пригодность инициированного скриптом входа для браузера покупателя
пока не проверены. Веб-API Claude здесь не выдумываются и успех не имитируется.
Секретные данные не добавлялись в репозиторий или конфигурацию среды.

Используйте готовую сборку из `dist/`, как описано в `INSTALL_PLUGIN_RU.md`.
В созданном `storage/claude_rental/config.json` после реализации адаптера
укажите абсолютный путь в `claude_provider_file`, а отправителя задайте в меню.
Исходная версия из корня репозитория по-прежнему использует соседние
`rental.py` и `remail.py`; это вариант для разработки. У вспомогательных файлов
есть отметка `noplug`, чтобы Cardinal не загружал их как самостоятельные плагины.
Для старых интеграций сохранён вариант `provider_file` с готовыми методами
`issue`, `usage`, `revoke_all`; `issue` возвращает ссылку либо словарь
`{"value": "код или ссылка", "message_id": 5012}`.
Для добавления аккаунтов используйте меню. При работе с исходниками и CLI
используйте ту же базу:

```sh
python rental.py --db /path/to/FunPayCardinal/storage/claude_rental/rentals.sqlite3 add
```

Отключите штатную автовыдачу Cardinal для этих же лотов, чтобы она не отправляла
товар параллельно. Запускайте только один экземпляр плагина на базу. Плагин
проверяет лимиты и окончание аренды каждые 30 секунд; фактическая задержка может
увеличиться на время запросов. После запуска нужны проверки с тестовым оплаченным
заказом, истечением аренды, перезапуском, сетевым сбоем и реальным отзывом сессий.
