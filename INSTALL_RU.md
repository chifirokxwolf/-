# Установка Claude Rental 0.1.0

## Что находится в архиве

| Файл | Назначение |
| --- | --- |
| `claude_rental_plugin.py` | Обработчик заказов FunPay Cardinal |
| `rental.py` | База аккаунтов, резервирование и сроки аренды |
| `remail.py` | Чтение писем через API Remail |
| `config.example.json` | Пример настройки |
| `test_rental.py`, `test_remail.py` | Автоматические проверки без реальных аккаунтов |
| `README.md` | Подробности поведения и ограничения |
| `INSTALL_RU.md` | Эта инструкция |
| `.gitignore` | Исключение базы и локальных настроек из Git |

Это текущая версия разработки, **не полностью готовый автопродавец**.
База, обработчик Cardinal и клиент Remail реализованы. Настоящий адаптер Claude
для запроса входа, получения лимитов и завершения всех сессий пока не написан
и в архиве отсутствует. Полную автоматическую аренду до его подключения
запустить нельзя. Проверить доступ к почте можно уже сейчас.

В архиве нет ваших секретных ссылок, токенов, аккаунтов и базы. Их нужно ввести
локально. Cardinal устанавливается отдельно; изученная версия:
https://github.com/sidor0912/FunPayCardinal

## 1. Распакуйте архив и проверьте Python

Откройте терминал в распакованной папке `claude-rental-0.1.0`.
Проект проверен на Python 3.12. Дополнительные пакеты для этих файлов не нужны;
сам Cardinal использует собственные зависимости.

Linux:

```sh
python3 --version
python3 -m unittest -v
```

Windows PowerShell:

```powershell
py -3.12 --version
py -3.12 -m unittest -v
```

Ожидаемый результат — `Ran 25 tests` и `OK`. Проверки используют искусственные
письма; успешные тесты не подтверждают доступ к вашему реальному ящику.

Далее команды приведены с `python3`. В Windows заменяйте его на `py -3.12`.

## 2. Добавьте аккаунт

Из той же распакованной папки выполните:

```sh
python3 rental.py add
```

На запрос `Email:` введите точный адрес почты аккаунта Claude.
На запрос `Pickup URL (hidden):` вставьте персональную ссылку Remail целиком
и нажмите Enter. Символы при вводе ссылки не показываются — это нормально.

Почта должна совпадать с параметром `email` в ссылке. Ссылка должна иметь вид
`https://remail.aishop6.com/pickup?email=...&token=...`.
Токен скрипт извлечёт сам. Пароль от почты, API-ключ Anthropic и ключ FunPay
эта команда не запрашивает.

Повторите команду для следующих аккаунтов. Данные появятся в
`data/rentals.sqlite3`. Команда добавления не обновляет существующие аккаунты:
при повторном добавлении той же почты SQLite сообщит о дубликате.

## 3. Проверьте чтение почты

```sh
python3 rental.py status
python3 remail.py --account-id 1 --show-senders
```

Вместо `1` используйте нужный `id` из `status`.
При успехе увидите сообщение `Remail API доступен`, число писем и список
отправителей. Тексты писем, коды и токены не выводятся. Ноль писем означает,
что API ответил, но в ответе сейчас нет писем; это не проверка получения кода.

У новых аккаунтов состояние `quarantine`: выдача заблокирована до проверки
завершения старых сессий и лимитов через Claude-адаптер. Это ожидаемое поведение.

Если письмо входа Claude уже есть, найдите его точного отправителя в списке.
Если такого письма ещё нет, запросите вход на официальном сайте Claude вручную,
дождитесь письма и повторите команду. Выберите адрес именно письма входа Claude.
Пример отправителя Microsoft из документации Remail для этой задачи не подходит.

## 4. Подготовьте файлы для Cardinal

Этот этап подготавливает размещение файлов. Включение полной автоматизации
потребует готового Claude-адаптера, описанного в следующем пункте.

Остановите свой экземпляр Cardinal обычным способом. В его каталоге расположите
файлы так:

```text
FunPayCardinal/
  plugins/
    claude_rental_plugin.py
    rental.py
    remail.py
  storage/
    claude_rental/
      config.json
      rentals.sqlite3
```

Скопируйте три Python-файла из архива в `plugins/`. Тесты туда переносить не нужно.
Создайте `storage/claude_rental/`, а затем скопируйте туда `config.example.json`
под именем `config.json`. Если такой файл уже существует, сохраните его и
перенесите нужные параметры вручную.

Если аккаунты уже добавлены на шаге 2, перенесите `data/rentals.sqlite3`
в `storage/claude_rental/rentals.sqlite3`, **только если целевой базы ещё нет**.
Существующую базу не заменяйте. Переносите базу при остановленных процессах.
После переноса используйте только её, чтобы не вести две независимые базы.

Из корневого каталога Cardinal команды теперь выглядят так:

```sh
python3 plugins/rental.py --db storage/claude_rental/rentals.sqlite3 add
python3 plugins/rental.py --db storage/claude_rental/rentals.sqlite3 status
python3 plugins/remail.py --db storage/claude_rental/rentals.sqlite3 --account-id 1 --show-senders
```

Если Cardinal работает в виртуальном окружении, используйте Python из этого
окружения. База содержит токены доступа к почте; ограничьте доступ к ней и к
резервным копиям. На Linux код выставляет права файла `0600`; на Windows
доступ дополнительно определяется правами пользователя и каталога.

## 5. Заполните конфигурацию

Откройте `storage/claude_rental/config.json` в текстовом редакторе:

- `database`: оставьте `storage/claude_rental/rentals.sqlite3`.
- `mailbox.allowed_senders`: впишите точный адрес отправителя письма Claude
  как строку внутри JSON-массива. Пустой массив запрещает получение кода для выдачи.
- `mailbox.poll_seconds`: интервал опроса, по умолчанию 5 секунд. Более позднее
  разрешённое время от Remail имеет приоритет.
- `mailbox.timeout_seconds`: время ожидания письма, по умолчанию 120 секунд.
- `rules`: готовое правило узнаёт предоставленное вами название лота и задаёт
  5 часов. Час за отзыв автоматически не добавляется. Количество товара пока
  не умножает срок (`quantity_is_duration` равно `false`).
- `claude_provider_file`: требуется путь к **реально реализованному** адаптеру.
  Путь в примере — обозначение места для будущего файла. Этого файла в архиве нет;
  простая замена пути на произвольный файл не добавит функциональность Claude.

На Windows в JSON записывайте пути с прямыми слешами, например
`C:/FunPayCardinal/custom/claude_provider.py`, либо удваивайте обратные слеши.

Адаптер должен предоставлять `create(config)`, возвращающий объект с методами:

```python
request_login(account, order_id)  # запросить отдельное письмо входа для покупателя
usage(account)                   # вернуть реальные проценты за 5 часов и 7 дней
revoke_all(rental)               # True только после проверки отзыва доступа
```

Формат и требования к этим методам подробно описаны в `README.md`.
Без них Cardinal не сможет выдавать аккаунты и завершать аренды. Постоянная
сессия скрипта сама по себе не отключает сессии покупателей.

## 6. Запуск после подключения Claude-адаптера

Запускайте Cardinal из его корневого каталога привычным для вашей установки
способом. Аутентификация FunPay остаётся в настройках самого Cardinal.
Для соответствующих лотов отключите его штатную автовыдачу, чтобы два механизма
не отправляли товар одновременно. Используйте один экземпляр плагина на базу.

Перед реальными продажами проверьте отдельным тестовым заказом:
получение нового письма, доставку кода покупателю, работу таймера, восстановление
после перезапуска, блокировку по лимиту и фактическое прекращение доступа
покупателя после аренды. Эти проверки на настоящих сервисах пока не выполнены.

## Частые результаты и ошибки

| Результат | Что означает / что проверить |
| --- | --- |
| `Account not found` | Указан другой ID или путь к другой базе |
| `Pickup URL must contain...` | Адрес почты не совпадает со ссылкой, отсутствует токен или неверный URL |
| `Remail HTTP 401` | Токен отсутствует, истёк или недействителен |
| `Remail HTTP 403` | Сервер либо сетевой прокси запретил доступ; проверьте токен и доступ к домену |
| `Remail transport or JSON error` | Ошибка сети, TLS или ответ не является JSON; не отключайте проверку TLS |
| `No module named remail` | `remail.py` не находится рядом с `rental.py` |
| `quarantine` | Для нового аккаунта ещё не подтверждены завершение старых сессий и лимиты |
| `hold` | Лимит превышен, данные устарели или проверка не удалась |
| Аккаунт `ready`, но не выдаётся | Он может быть занят текущей арендой; состояние аренды учитывается отдельно |
| Не найден `validated_claude_provider.py` | Реальный Claude-адаптер пока не подключён |

Состояние `ready` в таблице аккаунтов само по себе не означает, что аккаунт
свободен: выдача дополнительно проверяет незавершённые аренды в базе.
