# Авто-кик Claude Rental 0.4.2

Для версии 0.4.2 используйте `tools/claude_account.cmd`: пункт 1 — ручной вход,
пункт 2 — проверка. [Обновление и восстановление браузера](UPDATE_0.4.2_RU.txt).


Установите `plugins/claude_rental_plugin.py` через `/upload_plugin` и перезапустите
Cardinal. Перед обновлением остановите Cardinal и сохраните резервную копию
`storage/claude_rental/`. Не удаляйте базу и сохранённые профили браузера.

На Windows распакуйте `claude-rental-plugin-0.4.2.zip` в папку Cardinal.
В архиве плагин и обновлённые tools. Для работы только плагина достаточно одного
Python-файла, но старую привязку профиля нужно обновить инструментом проверки.

1. Запустите `tools\setup_claude_check.cmd` тем Python, которым запускается Cardinal.
2. Для каждого аккаунта выполните вход через `tools\open_claude_manual.cmd`.
   Выберите его ID из меню Cardinal и установленный Chrome/Edge.
3. Закройте окна этого профиля и запустите `tools\check_claude_account.cmd`.
   Используйте тот же ID и браузер. Подтвердите почту. Проверка сохраняет
   почту вместе с ID организации; старый файл привязок без почты требует этой проверки.
4. Запустите Cardinal на том же компьютере и под тем же пользователем Windows.
   В меню `/claude_rental` авто-кик включён по умолчанию (`auto_kick: true`).
   Продажи могут оставаться на паузе. Сам плагин должен быть включён.

Проверка истечения срока выполняется отдельным потоком каждые 5 секунд.
Задержки браузера и сети добавляются к этому времени; точность до секунды не обещается.
Срок берётся из существующей SQLite-базы: `rentals.expires`, состояния `active`
и `issuing`. Ручная покупка/выдача вне этой базы автоматически не обнаруживается.
Продление и бонус, записанные до окончания, учитываются. При остановленном
Cardinal авто-кик не выполняется; просроченные записи обрабатываются после запуска.

Бот сверяет организацию, нажимает «Log out of all devices» / «Выйти везде»,
подтверждает действие и проверяет старую браузерную авторизацию в отдельном
контексте. Данные сессии для проверки находятся только в памяти.
Глобальный выход завершает также сессию владельца. Перед следующей арендой
потребуется новый вход владельца.

В «Аренды» выводится результат:

- `browser_revoked`: кнопка нажата и прежняя браузерная авторизация отклонена;
- `retry`: результат не подтверждён, повтор через 60–300 секунд;
- `working`: попытка выполняется; после аварии будет повторена с задержкой.

При `rerun_account_check` обновите привязку через check; при
`browser_logout_unconfirmed` проверьте ручной вход, доступность Claude, диалоги и
проверку безопасности сайта. После неясного результата глобального выхода
владелец может уже оказаться разлогинен: нужен ручной вход, а не удаление базы.
Сетевые ошибки, чужая организация и неопознанная страница не считаются успехом.
Несколько процессов защищены блокировкой, успешный выход не повторяется после
перезапуска. Секреты и содержимое браузерных ошибок в базу/Telegram не записываются.

Это этап автоматического глобального выхода. `browser_revoked` оставляет аренду
в `cleanup` и аккаунт занятым: тест браузерной сессии не доказывает отзыв токенов
Claude Code и невозможность повторного входа по ранее выданной ссылке.
Новые выдачи, автоматический повторный вход владельца и возврат аккаунта в пул
этим обновлением не подключаются. Полный внешний Claude-адаптер, если он уже задан,
сохраняет управление завершением аренды; встроенный авто-кик тогда не запускается.

Проверки выпуска используют временные SQLite-базы и настоящий Chromium с локально
подставляемыми страницами. Живой аккаунт Claude и Claude Code в облачной среде
не авторизованы, поэтому их фактический отзыв не проверен. Для первого живого
испытания используйте собственный тестовый аккаунт и отдельный контрольный вход.
